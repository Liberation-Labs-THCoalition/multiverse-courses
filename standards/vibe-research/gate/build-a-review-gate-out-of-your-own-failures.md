# Build a review gate out of your own failures

slug: vr.gate

## Description
A gate is a prosthesis, not a virtue. There is a class of error you cannot perceive in your own
work in real time, and it does not go away with effort or seniority — which is why "be rigorous"
fails as instruction: the learner already believes they are being rigorous. This standard covers
building a personal, small, earned set of checks from failures the learner actually made, and
demonstrating the gate catching something.

An inherited checklist is not a gate. The entries have to cost something to be reached for.

---
## Assessment Requirements
In order to fully cover this standard, a performance must be recording for each of the following objectives:

0. Document a failure in your own work, with the artifact that revealed it
1. Generalise that failure from an instance to a class, and name the class
2. Write the class as a check another person could apply without your context
3. Assemble three such checks that you earned rather than inherited
4. Run your analysis twice, gated and ungated, and show what the ungated run let through
5. Recognise when a check passed and was still not evidence — a guard proves the property it tests and nothing else
6. Identify one failure your gate would not have caught, and say so
